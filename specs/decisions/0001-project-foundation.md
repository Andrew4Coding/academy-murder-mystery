# 0001: Project foundation

## Context

This project was generated by the `swiftui-app-scaffold` skill. This record captures the decisions it baked in, so later changes can supersede them explicitly.

## Decision

- **XcodeGen**: `project.yml` is the source of truth, and `MurderMystery.xcodeproj` is generated and gitignored. This avoids `pbxproj` merge conflicts.
- **One project with Shared + one target per platform**:
  - `Shared/` compiles into every app target. Each target folder keeps only its entry point, navigation, assets and entitlements.
  - App targets share the module name `MurderMystery`, so `Tests/Shared/` runs in every test bundle.
- **MVVM + repositories**: `@Observable @MainActor` view models, with `SwiftData*Repository` as the only `ModelContext` owner. The composition root is `AppEnvironment`.
- **Versioned SwiftData from V1** (`SchemaV1`, `AppMigrationPlan`), with Swift 6 strict concurrency.
- **Independent versions**: one `.xcconfig` per target, bumped with `fastlane bump app:<slug>`.
- **Fastlane + Xcode automatic signing**: shared lanes plus one platform block per target. The build number comes from TestFlight.
- **Spec-driven development**: `specs/`, with feature specs approved before any code.
- **Conventions, enforced by hooks and CI**:
  - commits: `type(scope): [ABC] summary`, microcommits, no AI attribution
  - branches: `<type>/<optional-spec-id->kebab-name`
- **Branches**: feature → `dev` (squash) → `staging` → `main` (merge commits). CI runs the build and test jobs only for `main`.
- **Agent setup**: `.claude/` holds rules, skills (`codebase-sync`, `commit`, `new-feature`) and a Stop hook. The hook compares a content fingerprint, so the baseline survives squash merges.

## Consequences

- Positive: the structure is consistent for humans and agents, shared code is tested on every platform, and conventions are checked mechanically.
- Negative: `Shared/` changes must build every target. On `dev` and `staging`, build and test failures surface late, so run the tests locally.
